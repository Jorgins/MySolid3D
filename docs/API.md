# MySolid3D — API для нейросетей и скриптов

MySolid3D — параметрический CAD (эскизы → бобышки, вырезы, скругления). Программа умеет принимать команды по
локальному HTTP и строить модели: вы шлёте JSON — деталь строится в окне и тут же возвращается результат
(ошибки, габариты, список граней и рёбер). Человек видит деталь в реальном времени и может отменить любой шаг
обычным Ctrl+Z.

Эта же инструкция отдаётся самой программой: `GET http://127.0.0.1:8765/`.

## 1. Подключение

1. Запустите программу с ключом `--api` (порт по умолчанию 8765): `mysolid3d.exe --api` или `--api=9000`.
   Либо включите галочку «API для нейросетей» в меню «Файл». Адрес пишется в строке состояния.
2. Проверка: `GET http://127.0.0.1:8765/health` → `{"ok":true,"app":"MySolid3D"}`.
3. Команды: `POST http://127.0.0.1:8765/api`, заголовок `Content-Type: application/json`, тело — JSON.

Безопасность: сервер слушает только `127.0.0.1`; запросы из браузера (с заголовком `Origin`) и с чужим
именем хоста отклоняются, CORS нет. Через API можно читать и писать файлы по путям, которые вы передали
(`open`, `save`, `export`, `sketch_import_svg`), поэтому включайте его только на своей машине.

Три способа работать:
- **Прямой HTTP** (любой язык). Пример на curl:
  `curl -s -X POST http://127.0.0.1:8765/api -H "Content-Type: application/json" -d "{\"cmd\":\"state\"}"`
- **Python-клиент** `tools/mysolid_client.py` (только стандартная библиотека): `from mysolid_client import CAD`.
- **MCP-сервер** `tools/mcp_server.py` для Claude Desktop, Claude Code и других MCP-клиентов — см. раздел 8.

## 2. Формат запросов и ответов

Одна команда: `{"cmd": "имя", ...параметры}`. Ответ: `{"ok": true, ...}` или `{"ok": false, "error": "что не так"}`.

Пачка команд (выполняется по порядку, на первой ошибке останавливается): список `[{...}, {...}]` или
`{"commands": [...]}`. Ответ пачки: `{"ok": bool, "executed": N, "total": M, "results": [...]}`.
Пачки быстрее и удобнее: каждая команда видит результат предыдущей. Но номера (эскиза, рёбер, граней) из
ответа внутри той же пачки не подставить — их можно узнать только после выполнения. Поэтому типичный
порядок: пачка «создай эскиз» → прочитать `id` → пачка «добавь фигуры и вытяни».

Единицы: миллиметры и градусы. Все числа — JSON-числа (с точкой).

## 3. Модель данных

Деталь — список **элементов** по порядку построения. Элемент: эскиз, бобышка (вытягивание), вырез, скругление, фаска.
Каждый элемент имеет числовой `id` (его возвращают команды) и имя. Операции ссылаются на эскиз по его `id`.
Деталь пересчитывается после каждой команды; если элемент не построился, в ответе его поле `error` не `null`
(и деталь остаётся такой, какой была до него). **Всегда проверяйте `error`.**

### Плоскости и координаты эскиза

У эскиза своя плоскость и координаты (x, y) в ней, в мм. Начало координат — точка (0, 0).

| plane | оси эскиза в мире | нормаль (куда «вверх» у эскиза) |
|-------|-------------------|----------------------------------|
| `top` (сверху, XY)   | x → X, y → Y | +Z |
| `front` (спереди, XZ) | x → X, y → Z | −Y |
| `right` (справа, YZ)  | x → Y, y → Z | +X |

- `offset` сдвигает плоскость вдоль нормали на столько мм.
- `plane` может быть объектом `{"origin":[x,y,z], "normal":[nx,ny,nz]}` — произвольная плоскость.
- Эскиз на плоской грани готового тела: `{"cmd":"add_sketch","face": номер_грани}` (номера — из команды `faces`).

Бобышка вытягивает контуры эскиза **по нормали** на `depth` (с `flip: true` — против нормали). Вырез по умолчанию
идёт **против нормали** (вглубь материала), с `flip: true` — по нормали; `through_all: true` — насквозь.

Миры: Z — вверх. Эскиз на `top` с бобышкой `depth: 10` даёт тело от z=0 до z=10.

### Контуры, отверстия, области

- Фигура эскиза: `rect`, `circle`, `path` (ломаная/контур с дугами) и т. д. (раздел 5). Для вытягивания контуры
  должны быть **замкнуты**.
- Фигура внутри другой замкнутой фигуры того же эскиза становится **отверстием** (вложенность считается по чётности:
  внешний — материал, внутри него — дыра, внутри дыры — остров снова материал).
- `regions` у `boss`/`cut` — какие области вытянуть: список номеров фигур эскиза. Область — фигура без вложенных в неё
  (они её отверстия). Без `regions` берутся внешние контуры и «острова».
- Линии построения (`sketch_construction`) в тело не входят.

## 4. Команды

### Осмотр

| cmd | параметры | ответ |
|-----|-----------|-------|
| `state` | — | `file`, `features[]` (id, name, type, error, параметры; у эскиза — `plane` и `shapes[]`), `body` (габариты), `color`, `material` |
| `faces` | — | `faces[]`: `index`, `planar`, `center`, `normal`, `area` (мм²), `edges` |
| `edges` | — | `edges[]`: `index`, `mid`, `start`, `end`, `length`, `straight`, `closed` |
| `help` | — | список команд |

`body`: `has_body`, `min`, `max`, `size` ([x,y,z] габариты), `faces`, `edges` — счётчики. **Номера граней и рёбер
меняются после любой операции**, поэтому перед `fillet`/`chamfer`/`color` по граням/`add_sketch` по грани
запрашивайте `faces`/`edges` заново.

### Файл

| cmd | параметры |
|-----|-----------|
| `new` | — (пустая деталь) |
| `open` | `path` — файл `.ms3d` |
| `save` | `path` (необязательно, если файл уже задан) |
| `export` | `path` (`.stl` для печати или `.step`), `format` необязателен |

### Эскизы

| cmd | параметры | ответ |
|-----|-----------|-------|
| `add_sketch` | `plane` (`top`/`front`/`right`/объект) **или** `face` (номер грани); `offset`, `name` | `id` |
| `sketch_add` | `sketch` (id), `shape` — одна фигура, или `shapes` — список | `indexes` — номера добавленных фигур |
| `sketch_remove_shape` | `sketch`, `index` | — |
| `sketch_transform` | `sketch`, `index`, `op`: `move` (`dx`,`dy`) / `rotate` (`angle`, градусы) / `scale` (`factor`); `about`: [x,y] (по умолчанию центр фигуры) | — |
| `sketch_construction` | `sketch`, `shape`, `segment`, `on` | — (делает сегмент линией построения) |
| `sketch_import_svg` | `sketch`, `svg` (текст файла) или `path`; контуры в мм, центр — в (0,0) | `indexes` |

### Операции

| cmd | параметры |
|-----|-----------|
| `boss` | `sketch`, `depth`, `flip`, `regions`, `name` |
| `cut` | `sketch`, `depth` (или `through_all: true`), `flip`, `regions`, `name` |
| `fillet` | `radius` + рёбра: `edges` (номера из `edges`) и/или `faces` (все рёбра этих граней) и/или `all: true` |
| `chamfer` | `distance` (или `size`) + рёбра как у `fillet` |
| `set_feature` | `id` + что менять: `depth`, `flip`, `through_all`, `radius`, `distance`, `regions`, `name` |
| `delete_feature` | `id` (вместе с эскизом удаляются построенные на нём операции) |

Ответ операций: `{"id", "error", "body"}`.

### Внешний вид и прочее

| cmd | параметры |
|-----|-----------|
| `color` | `color`: `[r,g,b]` или `"#RRGGBB"` (или `null` — сбросить); `faces`: номера граней (без него — вся деталь) |
| `material` | `material`: `plastic` / `metal` / `glass` / `stone`; `faces` как у `color` |
| `undo`, `redo` | — |
| `view` | `name`: `iso`/`front`/`top`/`right` |

## 5. Фигуры эскиза (`shape`)

```json
{"type":"rect",   "x":0, "y":0, "w":40, "h":30}                 // левый нижний угол и размеры
{"type":"rect",   "center":[0,0], "w":40, "h":30}               // от центра
{"type":"circle", "cx":10, "cy":10, "r":5}                      // или "center":[x,y] и "d": диаметр
{"type":"polygon","points":[[0,0],[40,0],[40,10],[10,10],[10,30],[0,30]]}   // замкнутый контур
{"type":"polyline","points":[[0,0],[10,0],[10,10]]}             // незамкнутая ломаная
{"type":"line",   "from":[0,0], "to":[10,5]}
{"type":"arc",    "from":[0,0], "to":[10,0], "through":[5,3]}   // дуга через три точки
{"type":"regular_polygon", "cx":0, "cy":0, "r":10, "n":6, "rotation":0}   // r — радиус описанной окружности
{"type":"ellipse","cx":0, "cy":0, "rx":20, "ry":10}
{"type":"path", "points":[[0,0],[20,0,0.5],[20,20]], "closed":true}       // третье число — дуга, см. ниже
```

**Дуги в `path`.** Точка `[x, y, b]` — число `b` описывает сегмент **от этой точки к следующей**: `0` — прямой отрезок,
иначе дуга; `b = tan(угол_дуги / 4)`, плюс — против часовой стрелки. Полукруг — `b = 1` (против часовой) или `-1`.
Четверть окружности — `b ≈ 0.4142`. Для замкнутого контура последняя точка соединяется с первой, и у неё тоже
может быть `b`. Если сложно считать, используйте `arc` и скругления командой `fillet` на готовом теле.

Фигуры одного эскиза не должны пересекаться и самопересекаться (будет ошибка построения). Касание контуров по
линии тоже лучше избегать.

## 6. Рецепты

### Плита 40×30×10 с отверстием Ø6 по центру и скруглёнными вертикальными рёбрами

```json
[{"cmd":"new"},
 {"cmd":"add_sketch","plane":"top"}]
```
→ `{"results":[{...},{"id":1,...}]}` — берём `id` эскиза:
```json
[{"cmd":"sketch_add","sketch":1,"shapes":[
    {"type":"rect","x":0,"y":0,"w":40,"h":30},
    {"type":"circle","cx":20,"cy":15,"r":3}]},
 {"cmd":"boss","sketch":1,"depth":10},
 {"cmd":"edges"}]
```
Окружность внутри прямоугольника сама стала отверстием. В ответе `edges` вертикальные рёбра — прямые
(`straight: true`), у которых `start` и `end` отличаются по z (длина 10). Среди них будет и шов цилиндрической
стенки отверстия — по положению (`mid`) отберите только четыре угла плиты. Номера рёбер зависят от тела,
подставьте реальные из ответа (например, так вышло `[0, 1, 4, 7]`):
```json
{"cmd":"fillet","radius":3,"edges":[0,1,4,7]}
```

### Вырез на верхней грани

```json
{"cmd":"faces"}
```
Находим грань с `normal` ≈ [0,0,1] и наибольшим `center.z` (верхняя), её `index` = 4:
```json
[{"cmd":"add_sketch","face":4}]
```
Эскиз на грани: начало координат — центр грани, оси выбираются автоматически. После `add_sketch` прочитайте
`state` и посмотрите `plane` (`x`, `y`, `normal`), чтобы правильно расставить фигуры, затем:
```json
[{"cmd":"sketch_add","sketch":7,"shape":{"type":"circle","cx":0,"cy":0,"r":4}},
 {"cmd":"cut","sketch":7,"depth":5}]
```
Проще и надёжнее: строить сразу на мировых плоскостях со смещением — `{"cmd":"add_sketch","plane":"top","offset":10}`
даёт эскиз на высоте z=10, и координаты эскиза = координатам X, Y мира.

### Вырез по контуру из SVG

```json
{"cmd":"add_sketch","plane":"top","offset":10}
{"cmd":"sketch_import_svg","sketch":3,"path":"C:/work/logo.svg"}
{"cmd":"sketch_transform","sketch":3,"index":0,"op":"scale","factor":0.5,"about":[0,0]}
{"cmd":"cut","sketch":3,"depth":1.5}
```

## 7. Советы и типичные ошибки

- После каждой пачки читайте `error` у созданных элементов и `body.size`: сверяйте габариты с задуманными.
- Вырез не пересекает тело (он вне материала) — тело не меняется; проверьте высоту эскиза и направление (`flip`).
- «в эскизе есть незамкнутый контур» — используйте `polygon`, `rect`, `circle`, а не `polyline`/`line` для того,
  что вытягивается.
- «контур пересекает сам себя» — проверьте порядок точек.
- Скругление большого радиуса может не построиться (`error`): уменьшите радиус или выберите меньше рёбер.
- Скруглять и срезать фаской удобнее в конце построения, когда рёбра окончательно известны.
- Небольшие правки существующих элементов — `set_feature` (глубина, радиус, направление), а не пересоздание.
- Вы можете продолжить деталь, которую человек уже начал: `state` покажет всё, что есть.
- Если команда вернула `ok:false` в пачке, она остановилась: прочитайте `executed`, чтобы понять, что уже сделано.

## 8. Python-клиент и MCP

`tools/mysolid_client.py`:

```python
from mysolid_client import CAD
cad = CAD()                       # http://127.0.0.1:8765
sk = cad.add_sketch("top")        # id эскиза
cad.sketch_add(sk, {"type": "rect", "x": 0, "y": 0, "w": 40, "h": 30})
cad.boss(sk, depth=10)
print(cad.state()["body"])
```
Любая команда доступна как `cad.call("cmd", **параметры)` или `cad.batch([...])`.

`tools/mcp_server.py` — MCP по stdio (две функции: `mysolid_api` — выполнить команду или пачку, `mysolid_docs` — эта
инструкция). Подключение в Claude Desktop (`claude_desktop_config.json`) или Claude Code (`.mcp.json`):

```json
{"mcpServers": {"mysolid3d": {"command": "python", "args": ["C:/Project/MySolid3D/tools/mcp_server.py"]}}}
```
Программа MySolid3D при этом должна быть запущена с включённым API.
